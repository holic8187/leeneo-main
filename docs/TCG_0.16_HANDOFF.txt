1. 무한의 탑

편성·전투
- 서로 다른 인물의 소유 카드 4장으로 편성한다. 강화 단계와 카드 레벨을 반영하고,
  모험에 참여 중인 카드 사본은 기존 개인 레이드와 같은 검증으로 제외한다.
- 현재는 마감기한 드래곤을 재사용한다. 클리어하면 다음 층에 도전하며, 실패한 층은
  다시 도전할 수 있다. 별도의 일일 입장 횟수 제한은 구현하지 않았다.
- 각 전투는 최대 7턴이다. 카드 선택 순서대로 행동하고 카드 행동 사이에 보스가 행동한다.
  아군 행동 제한시간은 20초, 보스 및 추가 효과의 자동 진행 대기는 1초다.
  행동불능 카드는 건너뛴다. 시간 초과는 기본 공격으로 처리한다.
- 장시간 접속 종료 후에도 이미 지난 마감시각을 기준으로 자동 행동을 재생한다.
  앱을 다시 열었다고 이미 만료된 각 턴에 새 20초를 주지 않는다.
  이는 서버 상태 조회 때의 따라잡기 처리이며, 접속 종료 중 상시 실행되는 별도 전투 작업은 아니다.
- 서버가 공유 전투 엔진을 실행한다. 클라이언트가 보고하는 공격력·피해·승패로 층을 올리지 않는다.

층별 난이도
- HP = round(18,000 × 층수^1.7), 상한은 Number.MAX_SAFE_INTEGER / 4.
- 기본 공격 피해 = 5 + floor(√층수 × 2). 1층은 HP 18,000 / 기본 피해 7이다.
- 보스 내부 단계 = min(8, 1 + floor((층수 - 1) / 5)).
- 6층부터 무작위 2명 공격, 11층부터 전체 공격, 16층부터 최고 공격력 대상 봉인,
  21층부터 전체 공격·화상, 26층부터 최대 HP 4% 보호막,
  31층부터 전체 공격·피해량 감소가 차례로 추가된다. 이후에도 HP와 기본 피해는 계속 상승한다.

증강 선택·유지
- 총 24종: 실버 8종 / 골드 8종 / 프리즘 8종. 모두 실제 전투 효과를 연결했다.
- 처음 시작할 때 3개 중 1개를 선택한다. 5층, 10층, 15층 등 5층 클리어마다 다시 선택한다.
- 후보 등급 순서는 시작 실버 → 5층 골드 → 10층 프리즘 → 15층 실버로 반복한다.
- 제시된 후보 각각을 1회 무료 재추첨할 수 있다. 즉 3개 슬롯을 각각 최대 한 번 바꿀 수 있다.
  재추첨 결과는 같은 등급이며 현재 보이는 다른 후보와 겹치지 않는다.
- 조회·앱 재시작으로 후보를 새로 뽑을 수 없다. 후보와 재추첨 사용 내역은 서버에 저장된다.
- 선택한 증강은 그달의 탑 도전에서 누적 유지한다. 이전에 고른 증강을 나중에 다시 선택해
  중첩할 수 있으며, 월이 바뀌면 초기화된다. 개별 전투의 행동 횟수·임시 보호막은 새 전투에서 시작한다.

월간 순위·보상

  덮어쓰지 않고 동결한다. 진행 중인 이전 달 전투는 새 달 진행으로 이어지지 않는다.

- 점수가 0인 계정은 월간 보상을 받지 않는다. 화면 표시 범위 밖의 양수 점수 참가자도 정산 대상이다.

    2~3위     :  70,000코인 + SR 이상 확정팩 3개
    4~10위    :  50,000코인 + SR 이상 확정팩 2개
    11~30위   :  30,000코인 + 고급 카드팩 3개

  먼저 전체 지난달 점수를 동결한 뒤 순위를 계산하고, 지급할 순위·보상·우편을 고정 저장한다.

  우편 수령 후 삭제에도 중복 지급되지 않는다. 우편함이 가득 찬 계정만 지연시키며 기본 재시도는 1시간이다.

2. 실시간 PvP

편성·능력치 변환
- 서로 다른 인물의 소유 카드 4장, 모험 참여 사본 제외. 강화·레벨·장착 장비를 반영한
  편성을 서버에서 검증한다. 해당 전투를 위한 사본 능력치를 사용하며 원래 소유 카드는 변경하지 않는다.
- PvP 최대 HP = 원래 카드 최대 HP ×50, 공격력 = 원래 카드 공격력 ×0.1.
  예: 원래 HP 100이면 PvP HP 5,000. 레벨로 오른 HP에도 같은 배율을 적용한다.
- 기존 스킬 엔진을 공유하고 상대 카드 파티에 맞춰 대상·반격·보호막·약화·복제·지연 효과를 연결했다.
  HP 비율 조건은 변환된 최대 HP 기준이다. SSR 구마의 저장 피해 반격 배율은 PvP에서
  저장 HP 50을 보스전 HP 1로 환산해, HP 변환 때문에 50배 과증폭되는 것을 막는다.

매칭·입장
- 시즌 시작 평점 1,000. 기본 매칭 허용 차이 150점, 대기 30초마다 50점씩 확대,
  상한 600점. 양쪽 허용 범위 중 더 작은 범위와 점수 차이가 가장 가까운 상대를 사용한다.
- 대기 유효시간은 90초이며 접속 상태 조회로 갱신된다. 준비 수락 제한은 30초다.
  준비가 만료되면 수락한 사용자만 다시 대기열로 돌아간다.
- 같은 계정끼리 매칭하지 않는다. 동시 입장·수락은 단일 서버 상태의 revision 비교 갱신으로
  처리하여 하나의 전투만 생성한다. 실제 입장 시 카드 소유·모험 잠금·기기 접속권을 다시 확인한다.

차례·종료
- 평점이 더 낮은 쪽이 선공한다. 동점이면 방에 먼저 배치된 쪽이 선공한다.
- A의 1번 → B의 1번 → A의 2번 → B의 2번 순서로 양팀이 번갈아 행동한다.
  각 팀은 자신의 카드 한 바퀴를 기준으로 턴과 쿨타임을 계산하고 행동불능 카드는 건너뛴다.
- 각 행동 제한시간 20초. 시간 초과는 기본 공격이다. 접속 종료 후 다시 조회해도
  원래 마감시각대로 자동 행동을 재생한다. 전용 상시 백그라운드 전투 작업은 아니다.
- 팀 브레이크는 100에 도달하면 0으로 초기화하고 그 팀의 다음 행동 차례 1회를 넘긴다.
- 상대 전멸 시 승리. 양쪽 전멸 또는 총 240행동까지 승부가 없으면 무승부다.
- 평점 변동은 Elo 방식, K=24. 점수는 0 미만이 되지 않는다.
- 종료 보상: 승리 600코인 / 패배 150코인 / 무승부 250코인.
  확정된 결과에만 보상이 생기고 수령은 계정 저장 revision·접속권·전투별 영수증을 함께 검사한다.
  중복 수령, 재시도, 서버 재시작으로 보상이 중복되지 않는다.

시즌
- 2026-10-19 월요일 00:00 KST를 기준으로 14일 단위 시즌이다. 새 시즌 평점은 1,000에서 시작한다.
- 경계를 넘겨 진행 중인 전투의 평점 결과는 그 전투가 시작된 원래 시즌에 정산한다.
  이전 시즌 종료 보상의 재수령 요청도 보존된 결과에서 처리할 수 있다.
- 2주 시즌 순위 보상은 미정이다. seasonRewardPolicy.enabled=false이며 자동 지급하지 않는다.
  탑 월간 보상이나 기존 개인 레이드 주간 보상과 혼동하지 않는다.

- 상해 UR: 물방울 최대 3개 저장·참격. SSR: 3턴간 보호막이 막은 직접 피해의 45%를 저장,
  다음 스킬 때 균등 보호막으로 분배. 수집 종료 후에도 5턴 쿨타임이 끝날 때까지 저장량은 유지한다.
  기본 저장 상한은 시전자 최대 HP의 120%이며 강화 수치를 적용한다.
- 멍프 UR: 보고서 최대 3개를 저장·방출. 기본 공격을 해도 보고서는 유지.
  SSR: 3턴간 최대 HP 25% 이상을 한 번에 잃은 생존 아군에게 피해 직후 회복·정화 1회.
- 쓰비 UR: 실제 제거한 약화로 먹물 최대 4개를 모아 전체 보호막으로 소비.
  제거할 약화가 없으면 회복. SSR: 지속시간형 약화를 최대 4턴까지 연장하고 추가 피해;
  동결·스턴은 연장하지 않는다.
- 잔디 UR: 계절 잎 최대 4개를 저장·방출. SSR: 봄의 심장 4개를 준비하고 이후 스킬을 사용한
  아군의 HP가 실제로 부족할 때만 심장을 소비해 그 카드 회복·보호막.
- 춘식 UR: 쉼터/다리를 번갈아 고르면 추가 정화/쿨타임 감소.
  SSR: 기본 공격마다 출발 도장 4개를 순서대로 소비해 점점 강해지는 추가 공격.
- 호이 HR: 환승표 3개를 기본 공격마다 소비해 행동 카드 쿨타임 감소·최저 HP 회복.

강화·행동·복제
- 스킬 수치 배율은 +0~+5 순서로 1.00 / 1.04 / 1.10 / 1.18 / 1.28 / 1.40.
  피해·회복·보호막·브레이크 등 효과량을 정수 반올림하고, 지속시간·타격 수·대상 수·쿨타임은
  그대로 둔다. 발동 조건의 HP 임계 비율도 강화로 바꾸지 않는다.
- 저장/방출 스킬의 CD 0 또는 1은 행동을 무료로 만드는 뜻이 아니다. 매 사용마다 그 카드의
  행동을 소비한다. 잔량이 없는 방출은 설명대로 저장 행동으로 처리한다.
- 조각당 효과는 각 조각의 강화된 수치를 먼저 반올림한 뒤 개수만큼 곱하여 설명과 맞춘다.
- SSR 호이 복제는 원본의 시전 정보·강화 및 관련 스냅샷을 사용하고, 호이의 공격력과
  복제 효과 배율 85%를 적용한다. 원본이 이후 사망해도
  복제할 수 있고 원본을 되살리지 않는다. 원본/복제자가 만든 저장 상태는 별도로 유지한다.
- 추가 발동은 일반 기본 공격과 구분해 큐로 처리한다. 원본 사망, 복제, 횟수 소비,
  실제 제거 여부, 행동불능 회복 방지, 전용 아이콘 설명을 회귀검사했다.

적 대상 수와 PvP 보정
- 모든 216종에 적 대상 프로필을 지정했다: 1명 168종 / 최대 2명 24종 / 최대 3명 12종 / 전체 4명 12종.
- 2명 효과는 대상당 피해·약화 수치 65%, 브레이크 85%; 3명은 50% / 70%; 4명은 40% / 60%.
  단일 대상은 100%다. 치유·보호막 등 아군 효과의 대상 수를 이 프로필로 바꾸지는 않는다.
- 보스전은 적 1체에 기존 계수를 적용한다. 실제 공격 효과가 없는 지원 스킬은 이 프로필이 있다고
  새 공격을 만들지 않는다. 기본 공격·반격 및 특정 대상에 묶인 씨앗/봉인은 별도 단일 대상 규칙이다.
- 선택한 적부터 대상 수를 채운다. 단일 효과는 도발을 따르고 한 행동 안에서는 대상을 고정한다.
  대상이 죽었다고 이미 걸린 씨앗·봉인·반격을 관계없는 적에게 옮기지 않는다.

4. 모든 카드 원화의 서버 제공 및 기기 캐시

원본·빌드
- 원본 파일은 tcg-desktop/public/assets/cards 및 해당 보스·유물 원화 폴더에 보존한다.
  원격 원화 빌드가 원본을 추가 압축·축소·삭제하지 않는다.
- build-card-art-manifest.mjs가 서버 카드 목록과 협동 보스·유물 원화에서 경로·SHA-256·바이트 수를
  생성하여 클라이언트 cardArtManifest.js와 서버 cardArtManifest.json에 함께 기록한다.
- 운영 HTTPS VITE_TCG_API_BASE가 지정된 production build는 기본적으로 원격 원화를 사용한다.
  TCG_REMOTE_CARD_ART=1로 명시 활성화, =0으로 개발용 로컬 포함을 선택할 수 있다.
  원격 주소는 자격정보·쿼리·경로가 없는 HTTPS API origin이어야 한다.
- 빌드 완료 시 정확히 매니페스트에 등재된 dist의 카드/보스 원화 사본만 제거한다.
  UI·로딩 캐릭터 등 다른 자산까지 전부 원격으로 보내는 구조는 아니다.
- 실제 production build는 누락 원화를 허용하지 않는 strict 매니페스트 검사를 사용한다.
  현재 진행 중인 그림의 파일 수·합계 용량과 최종 APK/PC 파일 크기는 아래 최종검증란에 기록한다.

서버 API
- GET /api/tcg/art/:filename?v=SHA256. 매니페스트에 있는 PNG/WebP만 제공한다.
  임의 경로·HTML·계정 데이터는 제공하지 않는다. 카드 원화는 공개이며 인증 쿠키를 사용하지 않는다.
- 정확한 파일명과 해시 버전은 365일 immutable 캐시. 이전 앱의 옛 해시 또는 PNG/WebP 확장자 요청은
  현재 검증된 원본과 새 해시·크기를 알리고 immutable로 고정하지 않는다.
- X-Card-Art-Revision / X-Card-Art-SHA256 / X-Card-Art-Bytes 헤더를 제공한다.
  브라우저 교차 출처 읽기를 허용하며 클라이언트는 같은 HTTPS 출처의 메타데이터만 신뢰한다.
- server.js에서 public art 라우트를 /api/tcg DB 준비 검사보다 먼저 등록했다.
  DB가 복구 중이어도 원화는 제공하고, 계정/저장 등 DB가 필요한 기능은 재시도 가능한 503을 유지한다.

기기 캐시·오프라인
- 계정 저장 DB와 분리된 IndexedDB hoi-card-art-v1에 이미지 Blob과 메타데이터를 저장한다.
  원화 캐시 상한은 200 MiB(209,715,200바이트). 동일 카드의 옛 캐시를 정리하고,
  상한을 넘으면 가장 오래 사용하지 않은 항목부터 제거한다. 이는 설치 파일 전체 용량 상한이 아니다.
- 한 이미지 최대 12 MiB, 다운로드 동시 3개, 요청 제한시간 15초.
  이미지 형식·길이·SHA-256을 검사하며, 저장된 이미지를 다시 읽을 때도 해시를 확인한다.
  fetch는 cache:no-store로 요청하여 별도 HTTP 캐시에 원본이 중복 저장되지 않게 한다.
- 동일 URL의 동시 요청은 하나로 합친다. 보이는 이미지의 메모리 URL은 유지하며,
  사용하지 않는 메모리 URL은 32개를 넘으면 정리한다.
- 화면 근처(350px 여유)의 원화만 읽고, 저장·다운로드 오류가 게임 진행이나 팝업을 막지 않는다.
  실패한 열린 이미지도 30초 후 재시도하며 네트워크 복구·화면 복귀 시 재시도한다.
  반복 이벤트는 5초 간격으로 제한한다.
- 이미 내려받은 원화는 오프라인에서 재사용한다. 없는 원화는 안내 자리표시자로 대체하고,
  카드 이름·등급·능력치·스킬 같은 코드 데이터는 계속 표시한다. 이 캐시가 서버 전용 Tower/PvP를
  오프라인으로 플레이하게 만드는 것은 아니다.
- IndexedDB 사용 불가 또는 저장 용량 부족이어도 네트워크에서 검증한 그림은 표시할 수 있다.
  앱 데이터 삭제/재설치나 기기의 저장 공간 정리 후에는 그림을 다시 받을 수 있다.

배포 순서 주의
1) 모든 최종 원화와 두 매니페스트가 맞는지 strict 검사·해시 검사한다.
2) 해당 원본·매니페스트·public art 라우트를 포함하는 서버를 먼저 배포한다.
3) 운영 API에서 원화의 응답·형식·바이트·해시와 기존 버전 URL 호환을 확인한다.
4) 같은 매니페스트 및 올바른 HTTPS API 주소로 클라이언트를 빌드하고 원화 제외 여부를 검사한다.
5) PC/Android 설치·처음 다운로드·재시작 캐시·오프라인 자리표시자를 확인한 뒤 클라이언트를 공개한다.
서버보다 클라이언트를 먼저 공개하면 아직 제공되지 않는 신규 원화가 자리표시자로 보일 수 있다.
예전 설치 파일을 되돌리거나 서버 원본만 교체할 때도 버전 URL의 호환 동작을 재확인한다.

5. 서버 동시성·데이터 보존과 검증 범위

- Tower: 월별 계정 문서, revision 및 rankingFrozenAt 조건부 갱신. 처리 도중 월 경계와
  활성 기기 접속권을 재검사한다. 같은 승리 재요청은 층·점수를 두 번 늘리지 않는다.
- PvP: 하나의 coordinator에 대기열 최대 128, 준비방+전투방 최대 32, CAS 재시도 최대 12회.
  확정된 종료 결과만 별도 archive에 보관한다. 전투별 actionId 영수증과 revision으로 중복 공격을 막는다.
  DB 대기 중 기기가 전환되어도 쓰기 직전 접속권을 재검사한다.
- PvP 전투는 최대 240행동, 공개 로그 최대 160개, 행동 영수증 최대 240개다.
  Tower 공개 응답은 최근 로그 100개만 보내며 전투 자체는 7턴으로 제한한다.
- 선택 입력은 실제 스킬 선택 enum만 허용한다. 임의 큰 객체·배열·문자열이 복제/전투 저장에
  유입되지 않는다. DB에 초기화되지 않은 클라우드 저장은 PvP에 입장할 수 없다.
- DB 준비 검사에서 저장 요청과 인증을 구분해 장애가 잘못된 로그인 만료로 취급되지 않게 한다.
  Tower 월간 정산 스케줄러는 DB readyState=1에서만 동작한다.
- PvP/협동 보상 수령 응답이 연결 복귀를 기다리는 동안에도 재접속 검증 GET을 허용한다.
  검증 GET은 진행 중 보상/UI 상태를 덮어쓰지 않는다. 동일 JWT 재접속에서 상호 대기를 없애며,
  보상은 기존 접속권·계정 epoch 검사 뒤 한 번만 반영한다.
- 계정별 장기 지급 영수증과 PvP 시즌 결과 영수증은 중복 지급 방지를 위해 보존한다.
  임의로 잘라내는 정리 작업은 이번 범위에 없다.
